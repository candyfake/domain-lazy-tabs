## 1.1.0 提前加载验证

`tests/browser-queue.cjs` 同样使用隔离的 Chromium 和本机 HTTP 请求计数，已通过：

- 真实中键依次打开 10 个不同的帖子：仅第 1～3 个发出目标请求，其余保持 0；来源主页不占名额。
- 手动激活第 8 个立即加载，原有 3 个自动名额保持；关闭第 1 个补第 4 个，关闭手动打开的第 8 个不补第 5 个。
- 自动加载的第 2 个离开受管域名后，第 5 个补位。
- 强制停止后台 service worker，确认调试目标消失；重新唤醒后确认全局内存标记已丢失，以此证明真实重启。3 个自动名额仍占用，新开的第 11 个继续等待；关闭第 3 个后按原顺序加载第 6 个。
- 只打开 2 个帖子时全部预加载。
- 按需模式仍保持后台零目标请求；等待标签的标题没有「待查看」前缀，favicon 来自扩展本地文件。

自动预加载名额并不是浏览器进程内存的硬上限，测试没有测量或承诺固定 MB 的节省。

等待页被 Chrome 主动 discard 后的队列唤醒有单元测试覆盖。真实浏览器额外测试可通过 `QUEUE_TEST_DISCARD=1` 启用，但本机 Chrome for Testing 151 无头环境执行 `tabs.discard` 时浏览器退出，默认跳过该额外路径；**不声称已通过真实 discard 恢复测试**。

边界：自动化采用无头 Chromium，不能点击操作系统的原生右键菜单条目。测试验证了可信右键事件中的 URL，以及用该 URL 打开后台页后的网络行为；不能把它说成完整的操作系统菜单点击实测。尚未在登录态 Linux.do 上验证所有主题、站点脚本和其他扩展组合。

复现命令见 README。两份浏览器测试使用本机 HTTP 服务器统计 `/target` 请求，不依赖目标站点响应，也不拿页面外观推断“零请求”。运行输出保存到被 Git 忽略的 `artifacts/`。默认 `npm run test:browser` 顺序运行原行为与队列两份测试。
